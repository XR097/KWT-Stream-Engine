# KSE 微架构

本文描述 KSE（KWT Stream Engine）的最终交付微架构：一个只适配 KWT-1 的固定功能 W4A8
推理引擎，以及它在 E203 SoC 中的集成方式。早期设计文档中的估算已按最终实测更新；
凡与最终 `strict-final` 实现不一致的地方，以实测报告和 `docs/spec/kse_*.md` 为准。
与早期版本相比，本文按最终交付删去了双 bank 并行、3×2 交叉开关和 16 路默认配置，
统一改为单口共享 SRAM、PF128 和 SM/LN 各 8 路。

## 1. 概述与设计目标

KWT-1 是 12 层 Transformer 编码器：输入 99 个 token、每 token 64 维，单头注意力，
FFN 为 64→256→64，输出 12 类关键词。KSE 把层序、张量形状、数值格式和调度全部硬连线，
没有可编程命令流、架构寄存器堆和地址检查器；它只做这一张网络的推理。

设计目标按优先级排列：

1. **降低单任务周期**：吞吐和单任务能耗都随周期数下降；
2. **控制计分面积**：面积上限 2.25 mm²，在不增加周期的前提下压缩；
3. **保持数值精度**：相对 FP32 参考的 Top-1 下降不超过 2 个百分点是合格门槛；
4. **计时完整**：从输入/参数开始装载到结果写回，包含传输、等待、调度和计算；
   每个任务必须完整传输一遍全部参数。

最终配置为 1024 MAC（R32×C32）、参数预取 FIFO 128 行、Softmax 与 LayerNorm 各 8 路。
更宽的阵列或更多的非线性路数在单口共享 SRAM 下不能转化为吞吐，只会增加面积和功耗，
因此没有进入交付配置。

## 2. 工艺、电压与频率

- 工艺：SMIC 40LL，RVT 标准单元。
- 工艺角：`tt_typical_max`，1.10 V，25 °C；SRAM 宏为 `tt1p10v25c`，`EMA=3'b010`。
- 目标频率：150 MHz（周期 6.667 ns）。
- PPA 口径：DC/PrimeTime/PrimePower，理想时钟、布线前、无 SPEF；不是物理签核。

选择这一工艺角是因为项目所用的 SMIC40 库只提供 `tt1p10v25c` 一组 SRAM 模型，与标准单元的
tt 1.10 V 25 °C 对应，能保证标准单元与宏同角一致。所有综合、时序、功耗和对照实验都在
同一条件下完成。

## 3. SoC 总体结构

```text
             E203 (RV32IMAC, ITCM/DTCM)
              |  BIU
   +----------+------------------+------------------+
   | O5 mem 0x4000_0000          | PPI O12 0x1100_0000 | PLIC 源 17
   v                             v                     ^
 +---------------------- kse_accel_sys (hfclk / bus_rst_n) ----------------+
 | kse_sys_bus: 一个上游 sirv_gnrl_icb_arbt（3→1，固定优先级）             |
 |     m0 = NPU DMA   m1 = 参数加载器   m2 = CPU (E203 O5)                  |
 |                          | 单个 32 位 ICB 从口                          |
 | kse_shared_sram: 1 个控制器 + 32 组 × 2 × RAMSP4096X16 = 512 KiB       |
 |     每拍至多一笔、一拍读、无 bank 并行、无第二个口                       |
 |     门铃进度寄存器 -> 引擎（严格 0 滞后放行）                            |
 | kse_eng_icb: MMIO / 命令队列(2) / 参数段队列(4) / 流式 DMA / IRQ         |
 |                          |                                               |
 | kse_top: 阵列、行存储 A/B、预取 FIFO、非线性单元                         |
 +-------------------------------------------------------------------------+
```

- **E203** 负责固件、逐层命令下发、中断和调度；窗口内大部分时间处于 WFI，由 PLIC 源 17 唤醒。
- **共享 SRAM** 是 System Bus 上一个普通的 32 位 ICB 从设备，容量 512 KiB，
  由 64 个 `RAMSP4096X16` 组成 32 组 × 2 宏的平坦 128K×32 阵列。
- **参数加载器**是测试平台中的 ICB 主设备，从镜像文件顺序写输入和参数；它没有直连 SRAM 的旁路。
- **KSE** 通过 `kse_eng_icb` 的命令队列、参数段队列和流式 DMA 与共享 SRAM 交互；
  引擎内部另有行存储、预取 FIFO 和计算单元。

## 4. 共享 SRAM 与参数加载

### 4.1 单口从设备

共享 SRAM 对外只有一个 32 位 ICB 从口：每拍最多接受一笔命令，读命令下一拍返回数据，
写命令在握手沿写入宏；响应未消费时 `cmd_ready` 为 0。物理上有 64 个宏，但同一拍只选中
一个组（一个低/高 16 位宏对），结构上不存在两个主设备同时读写不同地址的可能。

地址窗口为 `0x4000_0000..0x4007_FFFF`。任务布局（窗口内偏移）：

| 偏移 | 字数 | 内容 |
|---|---:|---|
| `0x00000..0x018BF` | 1584 | 输入激活（99×64 int8） |
| `0x018C0..0x4EB3F` | 79008 | 参数流 v3（12 层 × 6584 字） |
| `0x60000..0x618BF` | 1584 | 输出激活 |
| `0x7F000` / `0x7F004` | 1 / 1 | FLAG_START / FLAG_DONE |

### 4.2 一个仲裁器合并三个主设备

`kse_sys_bus` 例化 E203 上游的 `sirv_gnrl_icb_arbt`（只例化，不修改 `third-party/` 源码），
参数为 `ARBT_NUM=3`、`AW=DW=32`、固定优先级、一个响应 ID 表项。默认端口优先级为
**NPU DMA > 参数加载器 > CPU**。

固定优先级而不是轮询的理由：

- 单口下任务总事务数固定（162850 笔，见 4.4），轮询不会增加总带宽；
- 引擎参数流一旦断供，QKV、FC1、FC2 等参数密集阶段就停摆，DMA 应优先拿到已提交的数据；
- 加载器每写一个字最多再产生一个字给 DMA，最坏 1:1 交替，因此不会被饿死；
- CPU 只在窗口前写 FLAG_START、全部层完成且 DMA 排空后写 FLAG_DONE，窗口内只访问
  MMIO 和 PLIC，最低优先级不影响功能。

### 4.3 门铃与放行规则

加载器与 SoC 的边界只有 32 位 ICB 命令/响应信号。加载进度通过同一个主口写三个门铃寄存器：

| 地址 | 寄存器 | 语义 |
|---|---|---|
| `0x4008_0000` | BASE/INIT | 写 base，同时 WPTR=base、VALID=1、DONE=0 |
| `0x4008_0004` | WPTR | 写已提交的排他上界（字节地址） |
| `0x4008_0008` | DONE | 写 bit0 表示装载完成；读回 VALID/DONE |

加载器每 1024 字先收齐此前全部数据写的响应，再发布一次 WPTR；每任务共 81 笔门铃
（BASE + 79 次 WPTR（含最终指针）+ DONE）。引擎的 DMA 只读满足
`VALID && A >= base && A + 4 <= wptr` 的字，即只读加载器已经提交的数据（`REL_LAG=0`）。
门铃不访问 SRAM 宏，只占用同一从口的单笔事务。

### 4.4 计时窗口与整机下限

窗口起点是加载器第一笔 BASE 门铃写握手，终点是 E203 写 FLAG_DONE 的握手；复位、ITCM
装载、读文件和镜像生成不计时。窗口内必然发生的事务：

| 来源 | 笔数 |
|---|---:|
| 加载器写输入 + 参数镜像 | 80592 |
| NPU DMA 读输入 + 参数镜像 | 80592 |
| NPU DMA 写输出 | 1584 |
| CPU 写 FLAG_DONE | 1 |
| 门铃（BASE + WPTR + DONE） | 81 |
| **合计** | **162850** |

单口每笔事务占一拍，因此事务下限是 162850 拍量级；strict-final 实测每任务 **163328 拍**，
其中包含 E203 收尾、门铃等待和响应排空。从口的持续吞吐是 1 字/拍。

## 5. 参数流与预取

参数在离线阶段按引擎消费顺序打包成 32 位小端流（一次性格式转换，不计时）：

- 每层 6584 字，12 层共 79008 字；每层 18 个列块（q/k/v 各 2、proj 2、fc1 8、fc2 2）。
- 每层头部包含 score/context 移位、残差对齐、LayerNorm 和 GELU 的标量；随后按列块交织
  bias、逐通道移位码和 W4 权重。q/k/v 的 bias 全为 0，打包时删除并校验。
- 权重按 PE 行打包：每个归约块、每个 PE 行的 32 个 4 位槽对应 32 个输出通道。
- GELU 表和 Softmax 指数表不进参数流，由 RTL 内的 ROM 提供。

`kse_pfifo` 是 8 个 `RAMSP128X16` 并排的 128 行 × 128 位 FIFO（PF128）。加载器每拍取一整行
（一个 PE 行的 32 个 W4 权重），读优先；输入行先进入 2 行暂存，只在没有读的拍写入宏。
FIFO 让参数口在注意力、LayerNorm 和层边界继续接收数据，把“整层装载”变成细粒度流式供给。

## 6. MAC 阵列与行存储

### 6.1 阵列

- 1024 个 9 位有符号 × 8 位有符号乘法器，R=32 行（归约）× C=32 列（输出通道）。
- 权重驻留、激活流式：每个 PE 有 32 位驻留寄存器，可放 8 个 4 位 W4 槽，或 4 个 8 位槽
  （K/V、W8）；流式操作数每拍一行，从行存储读出后广播到各列。
- 流水为“读地址 → 存储数据 → S1 寄存 → S2 乘法与 4 输入部分和 → S3 累加 → 后处理三级 →
  写回”，II=1。累加器 24 位，冻结方案已验证不溢出。

### 6.2 行存储

行存储 A、B 各由 16 个 `RAMSP1024X16` 并排组成，行宽 32 字节、1024 行。两块存储独立，
使流式读和结果写落在不同的单口宏上。

| 存储 | 行地址 | 内容 | 生命周期 |
|---|---|---|---|
| A | 0–197 | X（token t 占 2t、2t+1） | IN/上一层 LN2 写；LN1 原位写 X1；LN2 原位写下一层 X |
| A | 200–595 | S（查询 t 占 4t..4t+3） | SC 写，SM 读 |
| A | 600–797 | ctx（2 行/token） | PV 写，PJ 读 |
| A | 800–997 | FC2 输出（2 行/token） | FC2 写，LN2 读 |
| B | 0–197 / 200–397 / 400–597 | Q / K / V（2 行/token） | QKV 写；SC 读 Q、K；PV 读 V |
| B | 0–395 | P（4 行/查询） | SM 写，PV 读 |
| B | 0–197 | proj（2 行/token） | PJ 写，LN1 读 |
| B | 200–991 | H=GELU(FC1)（8 行/token） | FC1 写，FC2 读 |

两个原位覆盖都安全：LN 阶段 token t 的输出行写入时，它的输入行已经读完；P 覆盖的是
SC 结束后已无用的 Q/K。

## 7. 每层数据流

一条命令执行一层编码器。层与层之间按命令串行，层内阶段在数据依赖和存储端口允许时重叠
（Softmax 与 SC、PV 与 Softmax 尾部、FC1 与 LN1、LN2 与 FC2 最后一个列块）；参数加载器
始终与计算并行。矩阵阶段对每个列块遍历全部 99 个 token，每个 token 连续 KB 拍
（每拍读一行 32 字节），第 KB 拍后该列块的 32 个输出经后处理写成一行。

| 阶段 | 驻留操作数 | 流式行 | 输出 | KB |
|---|---|---|---|---:|
| IN（仅 in_en） | — | act_in 每 8 字成一行 | A[X+r] | — |
| QKV | Wq、Wk、Wv | A[X+2t+kb] | B[Q/K/V+2t+cb] | 2 |
| SC：S=QKᵀ | K（列加载） | B[Q+2t+kb] | A[S+4t+cb] | 2 |
| SM：Softmax | — | A[S+4t+k] | B[P+4t+k] | — |
| PV：ctx=P·V | V（行加载） | B[P+4t+kb]（u8） | A[CTX+2t+cb] | 4 |
| PJ：输出投影 | Wproj | A[CTX+2t+kb] | B[PJ+2t+cb] | 2 |
| LN1：残差 + LN | — | A[X+2t+h]、B[PJ+2t+h] | A[X+2t+h]（原位） | — |
| FC1 + GELU | Wfc1 | A[X+2t+kb] | B[H+8t+cb] | 2 |
| FC2 | Wfc2（K=256） | B[H+8t+kb] | A[F2+2t+cb] | 8 |
| LN2：残差 + LN | — | A[X+2t+h]、A[F2+2t+h] | A[X+2t+h]（原位） | — |
| OUT（仅 out_en） | — | A[X+r] | act_out | — |

- **SC**：每个列块先把 32 个 key 的 K 行（每 key 2 行）列加载进 PE 列，最后一个列块只有
  key 96–98 有效，其余列一拍写 0；然后流式读 Q。V 不转置。
- **PV**：每个输出列块把 99 个 token 的 V 行行加载进 PE 行，token 99–127 对应的行写 0；
  P 的填充字节在 Softmax 中写为 0。
- **SM**：每个查询读 4 行，两个行缓冲交替：装载并求最大值 → 32 路查表求和 → 8 路除法；
  输出行写 B，字节 j≥99 写 0。
- **LN1/LN2**：每个 token 读两半，残差 32 路并行，单遍统计 Σx、Σx²；6 个 token 缓冲、
  信用计数调度，依次完成填充、统计/方差/isqrt、8 路除法与仿射。输出写回 A 有优先权，读等待。

在 strict-final 中，参数供应平均约 0.5 字/拍，QKV/FC1/FC2 等参数密集阶段比双 bank 版本
拉长约一倍；SC、SM、PV、PJ、LN 等非参数阶段不受影响。总窗口由单口事务数决定，
引擎的参数饥饿周期与加载器占用从口的周期重叠。

## 8. 数值格式与非线性单元

冻结方案为 A8、W4（逐通道 2 的幂尺度）、MAC 24 位、Softmax Q15 指数 + P7 概率、
LayerNorm Q12/Q12、GELU middle ROM。所有重定标都是 2 的幂移位 + 最近偶数舍入 + 饱和。

| 单元 | 运算 | 实现 |
|---|---|---|
| 后处理（32 路） | `sat8(shift(acc24 + bias16, sh))`；FC1 再查 GELU | 3 级：加 bias、移位饱和、GELU |
| GELU | `x<lo → 0`，`x>hi → sat8(shift(x, tail))`，否则 `ROM[x−lo]` | 组合，在后处理第 2 级 |
| Softmax | `q8=shift(s−max, q8_sh)`，查 257 项指数表，`p=clip(div_rne(e<<7, Σe),0,255)` | 32 输入最大值树；8 路流水除法器，8 位商，2 位/级 |
| 残差（32 路） | `sat8(shift(x,ax) + shift(y,ay))` | 组合，寄存一级 |
| LayerNorm | 单遍统计 `S=Σr`、`Q=Σr²`；`square_sum=64²Q−64S²`；`variance=rne(square_sum,18)`；`den=64·isqrt(vq)`；`n=div_rne(shift(64r−S,nsh),den)`；`out=sat8(shift(n·gamma,ash)+beta)` | 8 路除法，30 位商、2 位/级 16 拍；钳位/乘 gamma/移位/加 beta 各一级 |
| 整数开方 | floor sqrt，36 位输入，每拍 2 位结果 | 9 拍迭代，两个单元交替服务 token |

`square_sum = 64²Q − 64S²` 在整数上与参考的 `Σ(64r−S)²` 恒等，因此只需一遍统计。
商超过 30 位（只在方差接近 0 时出现）时钳到 2³⁰−1；此时加法后必然饱和，结果与精确商相同。
所有除法和开方都是寄存的恢复迭代，没有组合 `/`、`%`。

## 9. 最终实现结果

strict-final 的 12 任务 SoC 实测（SMIC40 RVT TT 1.10 V / 25 °C、150 MHz）：

| 指标 | 结果 |
|---|---:|
| 拍/任务 | **163328** |
| 吞吐 | **918.397335 tasks/s** |
| 整 SoC 面积 | 3.541626496 mm² |
| 计分面积 | **1.236966656 mm²** |
| 整 SoC 功耗 | **123.405948 mW** |
| 单任务能耗 | **134.377696 µJ** |
| 加速器 setup / hold | +0.0102758 / +0.0138704 ns |
| 12 任务回归 | 12/12 PASS，每任务 6336 字节 0 失配 |

计分面积包含引擎、引擎内部宏、包装/DMA、总线胶合、进度寄存器及其译码/响应逻辑、
PLIC 源 17 增量；只豁免共享 SRAM 和固定平台，功耗全部计入。相对上一版 strict PPA 优化，
门铃方案增加 336 拍（+0.206145%），但面积、功耗和能耗同时下降，Δscore 为 +0.351878。

## 10. 已知限制

- **单口串行化是主要代价**：加载器写 80592 字和 DMA 读 80592 字必须分时占用同一个 32 位口，
  引擎参数供应约 0.5 字/拍，参数密集阶段被拉长约一倍。这是“共享 SRAM 必须是 System Bus
  上单个普通从设备”的合规要求带来的固有成本。
- **固定优先级在契约外会饿死低优先级主口**：三个主口持续请求同一地址的对抗性流量会把
  加载器饿死；KSE DMA 的有限、单调、受水位约束的流量不在这一场景内，契约测试和 12 任务
  SoC 已验证加载器持续前进。
- **PPA 是布线前估算**：理想时钟、无 SPEF，仲裁器 `rspid` 旁路的 timing-loop 提示、异步复位
  输入和观察时钟输出的限制仍在，不能替代完整物理签核。
- **共享 SRAM 面积和固定平台不计入计分面积，但功耗计入整机**；评估能效时不能只看引擎功耗。
