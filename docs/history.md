# KSE 版本演进

本文记录 KSE（KWT Stream Engine）从首版 RTL 到最终交付版本的演进。每一版的数字都来自对应版本的
RTL 仿真、DC 综合与 PrimePower 实测；口径不相同的数字不混用。所有 PPA 结果均为 SMIC40 RVT
TT 1.10 V / 25 °C、150 MHz、理想时钟、布线前、无 SPEF 的估算，不能视为布线后或 PVT 签核。

> 版本命名说明：`asic-soc-v1` 指第一个完整 SoC 里程碑；此前的“优化轮 1”是引擎级改动，其成果随后
> 集成为 `asic-soc-v1`。`v2/opt2` 是第二个 SoC 里程碑上的评分消融。之后的 strict 系列因共享 SRAM
> 的合规要求重做了总线结构。

## 1. 引擎 RTL v1

首版把 KWT-1 的 12 层编码器全部硬连线：T=99 token、D=64、FFN 64→256→64、单头注意力，
没有可编程命令流和架构寄存器堆。阵列取 R32×C32（1024 个 s9×s8 乘法器），权重驻留、激活流式；
行存储 A/B 各 16 个 `RAMSP1024X16`；Softmax 与 LayerNorm 各 8 路。

- 功能：24 样本 × 12 层，40468032 项逐位一致，0 失配。
- 性能：单任务 163937 拍（时序修复前 160768），150 MHz 下 1.093 ms、915 任务/秒。
- 综合：引擎面积 1.171 mm²（含 32 个宏 0.293 mm²），setup WNS +0.0002 ns，
  hold 有 512 个端点违例（最差 −0.09 ns，均在 SRAM 宏 D 输入），留给后续轮次闭合。

## 2. 优化轮 1

目标是在面积增长有限的前提下压缩单任务周期，参数下限为每任务 79008 字（1 字/拍）。

- **参数预取 FIFO**：8 个 `RAMSP1024X16` 并排成 1024×128 位（16 KB），加载器每拍取一整行
  （一个 PE 行的 32 个 W4 权重）；参数流 v3 把字段补齐到 4 字整数倍，每层 6584 字。
- **驻留槽逐归约块门控**：FC2 第一个列块的前 6 个归约块可在 FC1 最后一个列块计算时装。
- **阶段重叠**：Softmax 与 SC 同时启动，PV 在 SC 后立即启动，FC1 在 LN1 期间启动，
  LN2 与 FC2 最后一个列块重叠；P 移到 B 存储区，不再覆盖 Q/K。
- **LayerNorm**：6 个 token 缓冲、信用计数代替固定冷却、除法阶段 token 间无气泡。
- **路数**：复核后取 SM/LN 各 16 路。

结果：单任务 101792 拍（−37.9%），150 MHz 下 1474 任务/秒（+61%）；引擎面积 1.401 mm²
（+19.6%），setup 0.000 ns、hold 最差 +0.01 ns，24×12 回归仍为 0 失配。

## 3. asic-soc-v1

把引擎集成进 E203 SoC：E203 负责逐层下发命令、中断与调度，测试平台参数加载器经共享 SRAM
写输入和参数，引擎 DMA 搬运，PLIC 源 17 唤醒 WFI 的 CPU。共享 SRAM 为 512 KB
（64 个 `RAMSP4096X16`），按地址条带交织成两个 bank，加载器与 DMA 可并行访问不同 bank；
加载器每拍至多写一个字，引擎只读已发布写指针之前的地址。

- 计时：从加载器第一笔写握手到 E203 写 FLAG_DONE，包含输入/参数传输、等待、调度与计算。
- 12 任务回归 12/12 PASS，76032 字节比较 0 不一致；每任务 103563 拍（0.690 ms），
  150 MHz 下 1448.4 任务/秒。
- 计分面积 1.410501 mm²（上限 2.25 mm²）；整 SoC 面积 3.716030 mm²。
- 12 窗口平均功耗 163.329205 mW（动态 162.849475、漏电 0.479731），
  单任务能耗 112.771388 µJ。
- 时序：加速器 setup/hold +0.000008080 / +0.009452038 ns；E203 +0.000000000 / +0.001766823 ns。
  加速器 setup 裕量只有约 8 fs，是后续版本持续关注的风险。

## 4. v2 / opt2

第二个 SoC 里程碑在完全相同的综合、活动和功耗脚本下做评分消融，最终选中 `ln_live`：

- 每任务 100794 拍（相对公平基线 −2.67%），150 MHz 下 1488.18 任务/秒。
- 计分面积 1.396560 mm²（−0.09%）。
- 整 SoC 功耗 165.355168 mW，单任务能耗 111.117614 µJ（−1.45%）。
- 相对公平基线的 Δscore = +0.505833（吞吐 +0.325216、能耗 +0.175100、面积 +0.005518）。
- 时序：加速器 setup/hold +0.010072626 / +0.013147108 ns。
- 12 任务回归 12/12 PASS，40468032 项网络比较 0 失配。

这一版保留了双 bank 共享 SRAM 和 3×2 交叉开关，加载器与 DMA 可以在不同 bank 上并行，
因此周期明显低于后续的 strict 合规版。

## 5. strict 合规版

合规要求把共享 SRAM 改成 **System Bus 上一个普通的 32 位单口从设备**：每拍至多一笔事务，
不得有 bank 并行、第二端口或私有 DMA 口。为此删除了 v2 的 3×2 交叉开关、两 bank 并行和
DMA 私有口，改为：

- 一个 32 位 ICB 从口，64 个 `RAMSP4096X16` 组织成 32 组 × 2 宏的平坦 128K×32 阵列；
- 从设备前一个上游 `sirv_gnrl_icb_arbt`（3→1，固定优先级 DMA > 加载器 > CPU），
  CPU、参数加载器和 NPU DMA 都经它访问 SRAM；
- 加载器仍是测试平台 ICB 主设备，但写入经同一仲裁器；放行规则取 `REL_LAG=0`，
  DMA 只读加载器已经提交的字；
- 引擎 MMIO、PLIC 源 17、命令队列和数值/golden 全部不变。

结果是单口串行化的固有代价：每任务 163015 拍，150 MHz 下 920.16 任务/秒，相对 v2
周期 +61.7%、吞吐 −38.2%。窗口内必然事务 162769 笔，理论下限 162923 拍（含 154 拍 E203
收尾），实测只高 92 拍（0.056%），从口利用率 99.85%。12 任务回归 12/12 PASS。
本轮明确不做 DC 综合和功耗，面积、时序、功耗留给下一轮重新测量。

## 6. strict PPA 优化

在单口约束下做面积/功耗优化，最终采用 PF128（预取 FIFO 从 1024 行缩到 128 行）与
SM/LN 各 8 路；R16×C32 候选也实际实现并测量，但周期和能耗上升、评分为负，未进入默认配置。

- 每任务 162992 拍，150 MHz 下 920.29 任务/秒（相对 strict 基线 −0.0141%）。
- 计分面积 1.238717 mm²（−11.4607%），整 SoC 面积 3.543828 mm²。
- 整 SoC 功耗 127.512464 mW，单任务能耗 138.563672 µJ（−10.8911%）。
- 相对 strict 基线 Δscore = +2.115769。
- 时序：加速器 setup/hold +0.0101485 / +0.0138704 ns，所有已约束路径组非负。
- 12 任务回归 12/12 PASS，24×12 网络 40468032 项 0 失配。

## 7. strict-final

最终版把加载器到 SoC 的五类非 ICB 进度端口全部删除，加载进度改为经 System Bus 上的门铃
寄存器发布：`0x4008_0000` BASE/INIT、`0x4008_0004` WPTR、`0x4008_0008` DONE。加载器仍是
一个 32 位 ICB 主设备，数据写和进度写都经同一个仲裁器；引擎只从片内进度寄存器得到放行信息，
`REL_LAG=0` 的“只读已提交字”规则不变。发布粒度取 1024 字，每任务 81 笔门铃。

- 每任务 163328 拍，150 MHz 下 918.397335 任务/秒；相对 strict PPA 优化版增加 336 拍
  （+0.206145%），门铃和等待全部计入计分窗口。
- 事务下限更新为 162850 笔（含 BASE、最终 WPTR、DONE）；12 任务实测与逐字节 golden 一致。
- 计分面积 1.236966656 mm²，整 SoC 面积 3.541626496 mm²。
- 整 SoC 功耗 123.405948 mW（internal 85.332829、switching 37.613307、leakage 0.459813），
  单任务能耗 134.377696 µJ。
- 相对 strict PPA 优化版 Δscore = +0.351878（吞吐 −0.024712、能耗 +0.368106、面积 +0.008484）。
- 时序：加速器 setup/hold +0.0102758 / +0.0138704 ns；E203 +0.000000000 / +0.026240000 ns；
  core/slow/jtag 等已约束路径组全部非负。
- 12 任务回归 12/12 PASS，每任务 6336 字节输出 0 失配；24×12 引擎回归沿用上一版结果
  （引擎 RTL 未改）。

## 8. 口径与限制

- 所有数字来自对应版本的仿真、DC 和 PrimePower 日志；不同版本的综合脚本、约束和活动文件
  可能不同，不能把不同口径的数字拼成同一配置的最优值。
- PPA 均为布线前、理想时钟、无 SPEF；仲裁器 `rspid` 旁路的 timing-loop 提示、异步复位输入
  和观察时钟输出的既有限制仍在，不能替代完整物理签核。
- strict 系列的低吞吐是“共享 SRAM 必须是 System Bus 上单个普通从设备”的直接代价；在保持
  这一合规前提的情况下，单口事务数已接近下限。
