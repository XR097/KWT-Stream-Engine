# 3 KSE 微架构

本章介绍 KSE 的微架构。我们先从共享存储的端口流量推出任务周期的下限，确定设计目标；然后依次介绍计算阵列、注意力、非线性单元、共享 SRAM 上的边载边算机制和层内调度；最后给出以评分函数为目标的设计空间探索。

## 3.1 设计目标与总体结构

吞吐和单任务能耗都随单任务周期的减少而改善，因此降低周期是首要目标；在周期不变的前提下，再尽量压缩面积。每个任务都要重新装载全部参数，每个参数字都要被加载器写入共享 SRAM 一次、被加速器读出一次，而端口每拍最多完成一笔事务。记输入与参数镜像的字数为 $W_{\mathrm{img}}$，输出字数为 $W_{\mathrm{out}}$，进度通知的笔数为 $N_{\mathrm{db}}$，则单任务周期满足

$$ C \;\geq\; 2W_{\mathrm{img}} + W_{\mathrm{out}} + N_{\mathrm{db}} + 1 = 2 \times 80{,}592 + 1{,}584 + 81 + 1 = 162{,}850 $$ (3-1)

式中最后一项是完成标志。这个下限只取决于平台接口和模型参数量，与加速器结构无关。因此 KSE 的设计目标可以表述为：让引擎的全部计算隐藏在端口流量之后，使任务周期尽量接近式 (3-1)。

KWT-1 的网络形状、层序和数值格式都是固定的，KSE 因此采用无指令流的固定功能结构（图 3-1）。网络形状直接编码在层定序器和地址生成逻辑中，E203 每层只下发一条命令。命令队列深两项，CPU 在第 $L$ 层计算期间下发第 $L+1$ 层的命令，随后进入低功耗等待，一条命令驱动约 1.3 万拍的计算。参数在离线阶段按引擎的消费顺序打包成一条顺序流，每层 6,584 字，12 层共 79,008 字。引擎的 DMA 只做顺序读，每个参数在每个任务中恰好读一次，从共享 SRAM 到阵列的整条路径不需要软件参与。

## 3.2 计算阵列

### 3.2.1 阵列规模

阵列规模要同时与参数供给速度和注意力计算量相匹配。共享 SRAM 端口被写入和读出平分，参数到达引擎的平均速率只有约 0.5 字/拍。消耗参数的矩阵乘阶段（QKV、FC1、FC2）因此受带宽限制，阵列再大也不会变快。不消耗参数的注意力阶段则受阵列算力限制。阵列取 1024 个 MAC 时，引擎各阶段都比端口流量快；减到 512 个 MAC 后，注意力阶段变长，引擎自身成为瓶颈，3.7 节的实验也证实了这一点。

阵列取 32×32 而不是 64×16，是由行存储的读带宽决定的。每拍从行存储读出的字节数必须等于归约维的宽度：32 字节的行只需 16 个 16 位宏并排，而 64 字节的行要用加倍的宏，否则每个 token 要读两拍，阵列只能发挥一半的吞吐。

### 3.2.2 数据流

所有线性层采用同一种数据流（图 3-2）：每次把 32 个输出通道的权重装入阵列的驻留寄存器，然后让 99 个 token 依次流过。每个 token 连续读入若干行，累加完成后，32 个输出经再量化写回一行。流式读和结果写分别落在 A、B 两块行存储上，因此矩阵乘阶段不会发生端口冲突。

每个乘法单元按 9 位 × 8 位设计。8 位一侧既能容纳 4 位权重，也能容纳注意力中的 8 位 K 和 V；9 位一侧既能容纳有符号激活，也能容纳无符号概率。这样 QKᵀ 和 PV 也能直接复用同一个阵列，不必拆成多遍计算。

![图 3-2 KSE 计算数据通路](figures/fig3-2_kse_datapath.pdf)

每个乘法单元的驻留寄存器可存放多组 4 位权重，组织成环形缓冲。当前列块计算时，加载器就把后续列块的权重预装进空闲的槽位。这样权重装载和计算并行进行，参数流不会因为阵列忙而停顿。

## 3.3 注意力

KWT-1 的序列长度只有 99，KSE 采用两段式注意力：先对全部查询算出分数矩阵 $S = QK^{\mathsf T}$ 并做 Softmax，再计算 $PV$。两次乘法都套用 3.2 节的数据流，K 和 V 分别作为驻留操作数，Q 和 P 作为流式操作数，V 不需要转置。

注意力的全部中间量（Q、K、V、S、P 和上下文）都留在片内的两块行存储中，不写回共享 SRAM。这一点在本平台上非常关键：共享 SRAM 端口已经被参数流占满，任何中间结果的往返都会直接延长任务周期。

为了缩短注意力阶段，分数计算、Softmax 和 PV 三段按 token 流水重叠：某个查询的分数写完，Softmax 就开始处理它；该查询的概率写完，PV 就可以使用它。行存储都是单口宏，我们按“不可停顿的写者优先”的原则仲裁读写冲突。此外，分数计算阶段采用成对调度：两个相邻列块的 K 一次装入驻留寄存器，每个查询连续与两组 K 计算，使 K 的装载次数和装载—计算切换次数都减半，而且不增加存储。

## 3.4 非线性单元

非线性单元与第 2.3 节的整数算法一一对应，各自是一条专用流水线，除法和开方都采用逐位迭代的寄存实现。

- **Softmax 单元**用最大值树求行最大值，并行查指数 ROM 并求和，再经多路流水除法器输出概率。两个行缓冲交替工作，使下一行的求最大值与当前行的除法重叠。指数表与模型参数无关，固化在 ROM 中，不占用参数流。
- **LayerNorm 单元**按式 (2-3) 一遍扫描得到统计量，每个 token 做一次开方，每个元素做一次除法。相邻 token 交替使用两个开方单元，逐 token 流水执行。
- **GELU** 串接在 FC1 的再量化流水中，只对中间段查表，两侧尾部用比较和移位直接得出结果。

## 3.5 共享 SRAM 与边载边算

### 3.5.1 单口共享 SRAM

共享 SRAM 由 64 个 4096×16 位单口宏组成 128K×32 位的平坦阵列，是系统总线上的一个普通从设备，读延迟一拍，持续吞吐为每拍一字。从设备前只有一个三选一的总线仲裁器，连接 CPU、参数加载器和 KSE 的 DMA。KSE 没有私有的存储端口，参数加载器也只通过一个 32 位总线端口写入。

### 3.5.2 写指针门铃

如果要等一整层参数写完才开始计算，装载和计算就完全串行。KSE 用写指针门铃实现边载边算：加载器每写完一批数据，就向进度寄存器发布新的写指针，DMA 只读取写指针以下已经提交的数据。计算在第一批参数提交后即可开始，此后参数的写入、读出和引擎计算在时间上交错进行（图 3-3）。注意力和 LayerNorm 阶段不消耗参数，加载器在这些阶段继续写入，引擎内的预取 FIFO 跨层连续接收参数。

![图 3-3 单口共享 SRAM 上的边载边算时序示意](figures/fig3-3_single_port.pdf)

门铃本身也要占用端口。发布粒度越细，DMA 越早拿到数据，但门铃笔数也越多。按 256 字发布时每个任务有 317 笔门铃，单任务 164,338 拍；按 1,024 字发布时只有 81 笔，单任务 163,328 拍。KSE 采用 1,024 字粒度。

### 3.5.3 仲裁策略

单口上一个任务的事务总数是固定的，只要端口不空闲，任何仲裁策略都受式 (3-1) 约束；仲裁决定的只是先服务谁。KSE 采用固定优先级 DMA > 加载器 > CPU。参数流一中断，矩阵乘阶段就会停顿，因此 DMA 优先；DMA 只能读到写指针为止，读完已提交的数据后自然让出端口，所以加载器的等待时间有界。计时窗口内 CPU 不访问共享 SRAM，与参数流没有冲突。表 3-2 比较了几种仲裁配置在完整 SoC 上的实测结果。

表 3-2 共享 SRAM 仲裁配置

| 优先级 | DMA 读取滞后 | 单任务周期 |
|---|---|---:|
| **DMA > 加载器 > CPU（采用）** | **0** | **基准** |
| DMA > 加载器 > CPU | 4 KB | +0.10% |
| 加载器 > DMA > CPU | 0 | +10.6% |

加载器优先时，引擎在整个装载期间几乎拿不到参数，周期增加 10.6%。采用方案下，单任务中共享 SRAM 端口的忙周期恰好等于式 (3-1) 的 162,850 拍，端口利用率为 99.7%。

## 3.6 层内调度重叠

每层依次经过输入、QKV、注意力分数、Softmax、PV、输出投影、LN1、FC1、FC2、LN2 和输出等阶段。如果严格串行执行，阶段之间会出现明显的空泡，参数流也会在注意力阶段中断。KSE 的原则是只增加控制逻辑、不增加存储，把相邻阶段改成按 token 重叠（图 3-4）。除 3.3 节介绍的注意力三段重叠外，还包括：

- FC1 在 LN1 期间启动，某个 token 归一化完成后即可流入 FC1；
- LN1 跟随输出投影逐 token 进行，LN2 在 FC2 的最后一个列块期间启动；
- 末层输出跟随 LN2 逐 token 写回共享 SRAM，不再等全部完成；
- LayerNorm 的仿射参数直接从加载器缓冲读取，不另设寄存器副本。

![图 3-4 层内阶段时序：串行执行与重叠调度](figures/fig3-4_layer_gantt.pdf)

在完整 SoC 上，中间各层每层约 12,800～13,900 拍。层与层之间的差异全部来自 QKV、FC1 和 FC2 这三个消耗参数的阶段，它们的长度随参数流到达的相位而变化；不消耗参数的注意力和 LayerNorm 阶段在各层的周期完全相同，说明它们都已隐藏在参数流之后。

## 3.7 设计空间探索

### 3.7.1 评价方法

每个候选配置都在完整 SoC 上走同一套流程：逐位功能回归、12 任务 SoC 仿真、整 SoC 综合，以及基于仿真活动的功耗分析。按赛题的评分权重，我们用相对某个基准配置的边际得分来比较候选配置：

$$ \Delta = 12\ln\frac{C_0}{C} + 12\ln\frac{E_0}{E} + 6\ln\frac{A_0}{A} $$ (3-2)

其中 $C$、$E$、$A$ 分别为单任务周期、单任务能耗和计分面积，下标 0 表示基准配置。

### 3.7.2 结果与分析

由 3.5 节可知，KSE 的周期已经由共享 SRAM 端口决定，引擎各阶段还有余量。所以只让引擎内部更快的方案无法降低周期，只会增加面积和能耗。探索的方向因此是：在不越过端口下限的前提下，尽量压缩引擎。基准配置为 32×32 阵列、1,024 行预取 FIFO、Softmax 与 LayerNorm 各 16 路除法器，结果见表 3-3。

表 3-3 设计空间探索结果（相对基准配置）

| 方案 | 周期 | 计分面积 | 单任务能耗 | Δ |
|---|---:|---:|---:|---:|
| 预取 FIFO 缩至 128 行 | 0.00% | −3.46% | −2.48% | +0.513 |
| 预取 FIFO 128 行 + 除法器 8 路（采用） | −0.01% | −11.46% | −10.89% | **+2.116** |
| 预取 FIFO 128 行 + 16×32 阵列 | +12.95% | −14.81% | +5.29% | −1.119 |

参数的平均到达速率只有约 0.5 字/拍，预取 FIFO 只需吸收短时的相位差，128 行已经足够，周期不变。除法器从 16 路减到 8 路后，Softmax 和 LayerNorm 阶段本身变长，但仍然隐藏在参数流之后，周期几乎不变；与预取 FIFO 的缩减合计，面积和能耗都下降约 11%。把阵列减半虽然面积降幅最大，但引擎在注意力阶段成为瓶颈，周期增加约 13%，能耗也随之上升，综合得分为负。

这组结果反映了 KSE 设计空间的基本特征：瓶颈在共享存储端口，而不在引擎。最优点就是把引擎压缩到恰好不成为瓶颈。采用方案的单任务周期为 163,328 拍，只比式 (3-1) 的下限多 478 拍（0.29%），其中 154 拍是最后一层完成后 CPU 处理中断、写完成标志的收尾时间。
